# 功能集字典页面平台化美化设计说明

## 1. 设计目标

本轮设计以当前 `功能集字典` MVP 页面为基础，不改变核心功能路径，重点提升页面的视觉完成度、信息层次和平台感。

目标如下：

- 保持当前“左侧选功能集、右侧看详情和版本”的主操作路径不变。
- 让页面整体风格更接近成熟的企业控制台，而非单纯原型页面。
- 参考“平台首页化”的视觉气质，但不复刻参考图的布局或内容。
- 兼顾后续继续扩展模块时的可维护性和一致性。

## 2. 设计范围

本轮只覆盖当前 MVP 已落地页面：

- 功能集字典
- 流程与交互说明
- 字段规范

其中视觉精修重点集中在 `功能集字典` 页面，其余页面保持同一设计语言同步提升。

## 3. 设计方向

采用 `B. 平台首页化风格`。

该方向的核心特征：

- 轻蓝白渐变背景
- 更清晰的大区块层次
- 更精致但克制的卡片系统
- 更统一的按钮、标签、表格、留白规则
- 页面顶部形成稳定的“业务总览卡”视觉锚点

不采用以下做法：

- 不做营销页式大面积视觉包装
- 不做偏大屏驾驶舱式重装饰
- 不增加与当前 MVP 无关的复杂模块

## 4. 页面结构方案

### 4.1 顶部总览卡

顶部区域升级为一个完整的业务总览卡，包含三层：

1. 标题、模块说明、右上角全局操作按钮（批量导入）
2. 查询区，支持按功能集名称和功能集编码检索
3. 三张模块说明卡，分别表达功能集定义、版本沉淀、操作日志回溯

设计目标：

- 进入页面先理解模块定位
- 查询入口放在全局说明区，不干扰左侧列表结构
- 三张说明卡成为轻量信息卡，而不是普通文本条

### 4.2 左侧功能集列表卡

左侧区域只保留：

- 功能集列表标题
- 数量统计
- 新增功能集按钮
- 功能集列表内容

明确去掉：

- 左侧列表卡内部查询区
- 与列表职责无关的额外说明块

设计目标：

- 左栏只承担“选择当前对象”的职责
- 列表项信息层次清楚：名称 > 编码 > 版本信息
- 当前选中项更明显，hover 更轻盈

### 4.3 右侧功能集详情卡

右侧详情卡继续保留当前信息结构，但提升视觉层次：

- 标题区：功能集名称 + 状态
- 说明区：功能集说明
- 信息区：功能集编码、版本数量、最新版本、创建人、创建时间
- 操作区：编辑、停用、删除

设计目标：

- 让当前对象识别更清楚
- 保持操作区存在，但不压过主信息

### 4.4 版本记录区

版本记录区保留现有能力：

- 版本列表 / 操作日志切换
- 新增版本
- 表格展示

但在视觉上统一到更成熟的工作区样式：

- 卡片头更整洁
- 切换器更平台化
- 表格头部、行距、状态标签和操作列更统一

## 5. 查询交互说明

查询能力采用“顶部轻量查询”模式：

- 支持字段：功能集名称、功能集编码
- 交互方式：输入即筛选
- 支持清空恢复全部列表

交互规则：

- 若当前选中功能集仍在结果中，则右侧详情保持不变
- 若当前选中功能集被筛掉，则自动切换到第一条匹配项
- 若无匹配结果，则左侧与右侧都显示空状态提示

不采用单独搜索按钮，也不引入复杂筛选器。

## 6. 模块说明卡设计

顶部三张说明卡升级为轻量信息卡，统一包含：

- 编号
- 标题
- 一句强调语
- 一段补充说明

三张卡的职责分别是：

- 功能集定义：表达当前模块负责维护能力边界
- 版本记录沉淀：表达当前模块负责沉淀可发布的能力快照
- 操作日志回溯：表达当前模块负责关键动作留痕

设计目标：

- 比纯文本条更清晰
- 比复杂统计卡更克制
- 作为页面理解入口，而不是数据展示卡

## 7. 视觉规则

### 7.1 背景

- 页面整体使用浅灰蓝底色
- 顶部和核心区域可使用非常轻的蓝白渐变与高光
- 不使用重色块，不抢主内容阅读

### 7.2 卡片

卡片分三级：

- 高优先级卡：顶部总览卡
- 主工作卡：列表、详情、版本记录
- 轻说明卡：顶部说明卡、说明页辅助卡

统一规则：

- 圆角适中
- 阴影轻、边框浅
- 主要依赖留白与标题层级分组，而非层层加边框

### 7.3 按钮

按钮分为三类：

- 主按钮：新增功能集、新增版本
- 次按钮：批量导入、清空
- 危险按钮：删除

统一规则：

- 主按钮强调色更稳定，不厚重
- 次按钮更轻
- 危险按钮减弱刺眼红边，保持明确但不跳脱

### 7.4 状态标签

- 启用、已发布：浅绿色底 + 绿色字
- 草稿、停用：浅灰底 + 深灰字

统一尺寸和圆角，确保在列表、详情、表格中风格一致。

### 7.5 表格

表格优化方向：

- 表头更轻
- 行距更舒展
- 操作列更整齐
- hover 更克制
- 状态标签与操作文案保持稳定节奏

## 8. 信息层次原则

页面需要明确四层关系：

1. 总览：顶部总览卡
2. 选择：左侧功能集列表
3. 对象：右侧功能集详情
4. 操作：版本记录与操作日志

目标是用户打开页面后能快速区分“这是什么、当前选中了谁、可以做什么”。

## 9. 响应式要求

桌面端为主要场景，移动与窄屏保持可用：

- 顶部说明卡、说明页卡片、详情信息区在窄屏时自动折行
- 查询区在窄屏下允许按钮换行
- 左右结构在窄屏时转单列

不追求移动端复杂重构，但要确保结构不破碎。

## 10. 实施顺序

建议按以下顺序实现：

1. 顶部总览卡视觉升级
2. 左侧列表卡和列表项精修
3. 右侧详情卡精修
4. 版本记录区与表格统一
5. 全局按钮、标签、阴影、边框与间距收口

## 11. 本轮不做

本轮明确不做以下内容：

- 新增平台级复杂导航
- 新增图表、仪表盘、统计概览
- 扩展机型绑定、软件版本映射、测试验收为真实页面
- 引入重动画、重插画、重营销式视觉元素

## 12. 验收标准

本轮完成后，应满足以下判断标准：

- 打开页面第一眼可明确识别“总览、列表、对象、操作”四层结构
- 查询区不再打断左侧列表布局
- 顶部三张说明卡更像成熟控制台中的信息卡，而非简单文本条
- 页面整体更轻、更稳、更完整，但仍保持管理页的清晰度
- 视觉升级不影响现有功能与交互逻辑
