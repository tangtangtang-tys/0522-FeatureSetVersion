# 功能集管理页面批注模式设计说明

## 1. 设计目标

为当前功能集管理页面增加一套“批注模式”，用于在平台页面内直接说明关键操作项的交互逻辑，减少研发人员在页面原型与需求文档之间来回切换的成本。

该模式参考墨刀类设计工具中的打点批注方式，但保持平台页面自身的阅读和操作体验，不引入过重的原型感视觉。

## 2. 设计原则

### 2.1 默认不打扰

- 页面默认保持普通视图
- 只有用户主动开启“查看交互说明”后，批注点与说明卡片才显示

### 2.2 只标关键操作

- 不对整页每一处元素都做说明
- 首轮只覆盖核心操作路径上的关键交互点
- 避免页面被过多标记打散阅读节奏

### 2.3 批注与 PRD 建立映射

- 每个批注说明应关联到 PRD 中对应的需求章节
- 研发看到批注后，可直接理解该操作逻辑来源

## 3. 承载方式

采用“批注模式开关”方案。

### 3.1 入口位置

建议在 `功能集管理` 页面右上角区域新增：

- `查看交互说明` 开关

### 3.2 交互方式

- 默认关闭
- 开启后进入批注模式
- 关闭后恢复正常页面

### 3.3 批注模式状态

#### 关闭状态

- 页面不显示编号打点
- 页面不显示批注说明卡片
- 页面保留原有视觉与操作结构

#### 开启状态

- 页面显示编号打点
- 关键区域旁显示对应说明卡片
- 说明卡片与页面结构相对固定，不遮挡主要操作

## 4. 批注覆盖范围

首轮建议只覆盖 8 类关键交互点。

### 4.1 查询区

说明内容：

- 支持按功能集名称、功能集编码检索
- 点击“查询”或按 Enter 执行
- 点击“重置”恢复全部列表

对应 PRD：

- 8.1.2 功能集查询

### 4.2 新增功能集

说明内容：

- 点击按钮打开新增功能集弹窗
- 字段包含名称、编码、状态、说明
- 名称、编码、说明必填
- 保存后列表与详情联动

对应 PRD：

- 8.1.3 新增功能集

### 4.3 左侧功能集列表项

说明内容：

- 点击列表项切换当前选中功能集
- 右侧详情与版本记录同步切换
- 查询结果变化时，若当前选中项不存在，则切换到第一条匹配项

对应 PRD：

- 8.1.1 功能集列表
- 8.1.2 功能集查询

### 4.4 功能集详情操作区

覆盖按钮：

- 编辑
- 停用 / 启用
- 删除

说明内容：

- 编辑：修改基础信息
- 停用：关闭后仅保留展示
- 删除：存在版本记录时禁止删除

对应 PRD：

- 8.1.4 编辑功能集
- 8.1.5 删除功能集

### 4.5 版本列表 / 操作日志切换

说明内容：

- 切换的是右侧工作区视图
- 不改变当前功能集
- 版本列表用于查看能力沉淀
- 操作日志用于查看关键动作留痕

对应 PRD：

- 8.2 模块二：功能集版本管理
- 8.3 模块三：操作日志

### 4.6 新增版本

说明内容：

- 点击后打开新增版本弹窗
- 支持保存草稿与发布
- 发布后形成正式版本快照

对应 PRD：

- 8.2.2 新增版本
- 8.2.3 保存草稿
- 8.2.4 发布版本

### 4.7 版本表格操作列

覆盖操作：

- 查看
- 编辑
- 发布
- 删除

说明内容：

- 查看：只读打开
- 编辑：可修改后保存 / 发布
- 发布：草稿转正式版本
- 删除：仅草稿可删除

对应 PRD：

- 8.2.5 查看与编辑版本
- 8.2.6 删除版本

### 4.8 批量导入

说明内容：

- 点击后查看导入模板说明
- 上传 JSON 文件并提交
- MVP 阶段可先保留原型提示

对应 PRD：

- 8.4 模块四：批量导入

## 5. 批注内容格式

每个批注说明卡统一采用精简结构：

1. 编号
2. 操作名称
3. 触发方式
4. 结果 / 校验逻辑
5. PRD 对应章节

示例：

```text
03 新增功能集
触发：点击按钮
结果：打开新增功能集弹窗
校验：名称、编码、说明必填
对应 PRD：8.1.3 新增功能集
```

## 6. 页面布局策略

### 6.1 打点样式

- 使用带编号的圆点或胶囊形标记
- 编号清晰、尺寸统一
- 颜色与当前平台主色保持一致

### 6.2 说明卡片

- 靠近对应操作区域展示
- 卡片尺寸适中
- 文案不写成长段
- 以研发快速识别逻辑为目标

### 6.3 避免遮挡

- 优先将批注卡片放置在操作区域外侧或空白区
- 避免覆盖表格数据、按钮和列表名称
- 在窄屏场景下允许改为垂直堆叠或简化显示

## 7. 页面间关系

### 7.1 与功能集管理页的关系

- 批注模式首先落在 `功能集管理` 页面
- 重点说明实际操作逻辑

### 7.2 与流程与交互说明页的关系

- `流程与交互说明` 页面保留整体逻辑与模块职责说明
- 批注模式负责将说明“贴”到具体操作点旁边

### 7.3 与产品需求文档页的关系

- `产品需求文档` 页面保留完整需求正文
- 批注模式在页面内通过章节映射，充当“研发快捷阅读入口”

## 8. 实施顺序

建议按以下顺序实施：

1. 新增页面右上角“查看交互说明”开关
2. 建立批注模式状态切换逻辑
3. 在 8 个关键位置增加打点
4. 为每个打点绑定说明卡片
5. 增加 PRD 对应章节映射说明
6. 对窄屏状态进行适配

## 9. 本轮不做

本轮明确不做以下内容：

- 对所有页面、所有字段逐一打点
- 允许用户自行新增批注
- 批注内容在线编辑
- 与外部设计平台的双向同步
- 将批注模式扩展到字段规范页和完整 PRD 页

## 10. 验收标准

本轮完成后，应满足以下标准：

- 用户可通过开关进入或退出批注模式
- 批注模式至少覆盖 8 类关键交互点
- 每个批注能说明操作触发方式、结果与关键校验逻辑
- 每个批注均可映射到 PRD 对应章节
- 批注模式不影响原有页面主操作路径
